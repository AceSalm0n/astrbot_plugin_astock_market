# A股大盘3—5交易日趋势分析设计

日期：2026-10-23。状态：用户已批准实施；功能开发、离线回归和公开历史接口只读核实已完成。AstrBot加载/重载及真实LLM已执行，最新提示词使用已配置Gemini Flash完成验收；QQ联调未执行，详见第12节。

## 1. 目标与取舍

采用方案二：插件查询历史日线，Python计算指标，LLM解释未来3—5交易日的趋势倾向、依据、反向证据及观察条件。首版定位为有依据的趋势研判，不承诺预测准确率；3—5日较适合本项目的日线输入与低频群消息，但不能据此断言比次日预测更准确。

候选方案比较：

| 方案 | 能力与代价 | 决定 |
| --- | --- | --- |
| 只改prompt | 输入仍只有行情快照，无法建立近期趋势依据 | 不采用 |

## 3. 预测口径与交易日历

### 3.1 固定基准

趋势基准为已完成交易日T的收盘价C(T)。观察区间为T之后第3至第5个交易日，不是3—5个自然日，也不是每次查询时重新计时的72—120小时。

输出固定标明：`趋势基准：T日收盘；观察区间：T+3至T+5交易日`。已知日历覆盖目标区间时同时显示实际日期；未覆盖时只显示相对交易日，不推算自然日期。

盘中查询可能已进入T+1：须标明“当前为T+1盘中观察，日线判断仍基于T收盘”。当日实时涨跌不并入历史累计涨幅、均线或全天成交额。模型只给一个3—5日总体倾向，可说明第3日观察条件与第5日延续风险，不输出次日涨跌结论。

### 3.2 年度日历与收盘缓冲

新增`assets/trading_calendar.json`，保存2025、2026年沪深交易所官方年度休市公告对应的工作日休市日期、来源URL、覆盖年份、核对日期和schema版本。周六日固定休市，调休上班周末也不开市。若两所安排有差异，分别存储；本次五指数的共同日历只在两者一致的日期上成立。

这是趋势分析的数据质量日历，不改原有推送调度或用户`market_closed_dates`。该配置继续控制原有调度；趋势入口另外只读检查它是否提示相关日期存在未核实临时休市。README须明确两个口径及年度更新责任。查询年份不在覆盖内、文件缺失或格式错误时，不猜测历史新鲜度，不输出趋势。

主流程将`market_closed_dates`传给`build_trend_context`作冲突检查。相关范围为截至T实际保留的历史窗口起日到T+5；目标年份未知时，未来部分不作日期推断，但历史和T的覆盖仍必须成立。配置中落在相关范围、且在官方已覆盖年份本应开市的日期为冲突，标记“临时休市需核实”并禁用本次趋势；范围外日期不影响本次分析。未来未知年份的配置只提示无法核实，目标保持相对T+3/T+5。非法日期项仅记录英文警告并忽略，不改写配置；官方本就休市的重复项不是冲突。

北京时间当天为交易日且早于15:15时，T取上一交易日；15:15及之后取当天。15:15仅是本插件给日线源的保守更新缓冲，不是交易所保证的数据更新时间。此时若源尚未提供当天完整日线，标为“日线更新中”，不把前日结果冒充新判断。周末和已核实休市日，T取最近交易日。

“存在T行”与“确认T行完成”是两项独立检查。任务1须为每个源记录可核实的日线归档/终值语义；当日T需有来源的明确完成标志及已核实语义，或与独立、已核实的盘后收盘行情四价一致的证据。不能凭日期、15:15、OHLC自洽或连续两次价格不变就判完成，不能虚构源的`is_final`字段。量额终值未确认时不使用量额指标。没有上述证据时，该源对当日T返回“完成状态未确认”，即使行存在也不合格；两个源都无法确认则本次不输出趋势。历史归档语义也须在任务1核实，未核实源只能参与显式标注的mock开发。具体证据字段及可用核对接口在任务1锁定，缺证据是实际适配验收的阻断项。

2026年10月23日为周五的测试例：15:14基准为10月22日；15:15后应要求10月23日日线；10月24日周六仍以10月23日为基准。国庆假期测试应确认10月1—7日不计交易日。

## 4. 历史行情接入与实施前检查

### 4.1 候选接口

拟采用东方财富日K主源、腾讯日K备用源。它们是候选公开接口，不能视为有稳定性承诺的正式API。实施任务1必须先核实五只指数的实际响应：

```text
Eastmoney:
https://push2his.eastmoney.com/api/qt/stock/kline/get
secid=1.000001 / 0.399001 / 0.399006 / 1.000688 / 1.000300
klt=101, fqt=0, lmt=80, end=当前北京时间YYYYMMDD
fields1=f1,f2,f3,f4,f5,f6
fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61

Tencent:
https://web.ifzq.gtimg.cn/appstock/app/fqkline/get
param=sh000001,day,,,80,qfq（替换对应sh/sz代码）
```

东方财富拟映射f51日期、f52开、f53收、f54高、f55低、f56量、f57额；腾讯拟映射日期、开、收、高、低、量。腾讯的`day/qfqday`选择及指数是否确实未复权，必须以响应和可核对的页面行情确认；不能因为参数写qfq就把复权序列接入指数。两源代码、顺序、币值和成交统计范围均需核实；不能只验证上证就声称覆盖全部。

原规划阶段：默认受限环境对两个域名均DNS解析失败，浏览工具也未取得接口正文。实施时经获准的只读网络检查，已取得五指数两源日线并验证各60根有效样本；默认受限环境的DNS失败并不代表数据源失效。当前采用的实际完成判据与证据见第12节。

如果备用源缺少某指数，明确该指数仅有主源；若两源都缺失则该指数趋势不可用，不新增付费源、账号或依赖来绕过。任何需要更换总体数据源的决定更新设计后再实施。

### 4.2 数据契约

`market_history.py`定义冻结dataclass：

```python
DailyBar(trade_date: date, open: float, close: float,
         high: float, low: float, volume: float | None,
         amount_yuan: float | None)

IndexHistory(code: str, source: str, bars: tuple[DailyBar, ...],
             fetched_at: datetime, from_cache: bool,
             amount_scope: str | None)

HistoryBatch(expected_date: date, histories: dict[str, IndexHistory],
             unavailable: dict[str, str])
```

- 单指数一次选择一整个来源，不把两源日线逐行拼接；跨指数允许来源不同并披露。
- 请求80根以容纳当日未完成行；验证后保留截至T最近60个已完成交易日。
- 最少21根连续且有效的日线，才能计算20日累计涨幅。21—59根可用但披露实际样本数；少于21根仅当前行情解读。
- 日期升序、去完全相同的重复行；同日期价格冲突、指数代码错、未来日期、最近窗口交易日缺失或OHLC无效，判该源无效并尝试备用源。不能删除坏行后把“最近20条”当20交易日。
- T必须恰好存在，窗口日期与覆盖范围内官方交易日历逐日匹配；不能因为多个指数同时漏一天就认定完整。
- OHLC必须为有限正数，`low <= min(open, close) <= max(open, close) <= high`。零量/零额保留为零；负数、NaN、Inf及缺失量额记未知，不污染有效价格。不能把未知金额填零。
- 金额统一元，原始单位由真实响应核实后锁定；量保留源已核实单位元数据。量不参与跨源比较。
- 腾讯金额字段未核实时固定为未知。主源有金额但统计范围未知时同样不计算金额比值。
- 历史金额只在同源、同指数、同统计范围的已完成日线之间比较；不与实时总成交额拼接，也不跨指数相加。

### 4.3 资源与缓存

`HistoryClient`由插件实例持有，独立管理aiohttp session，避免修改实时行情层内部状态。

```python
class HistoryClient:
    async def fetch(self, expected_date: date) -> HistoryBatch: ...
    async def close(self) -> None: ...
```

- 惰性建session；每源请求4秒，单指数两源链9秒，全批12秒，五指数并行。
- 成功缓存900秒、失败冷却60秒；缓存及在途请求键为`(code, expected_date)`。基准日期跨15:15或跨日后必须换键。仅成功/失败缓存淘汰旧基准；在途表须保留旧基准worker直至它结束或客户端关闭，不能为淘汰缓存而取消仍有等待者的请求。旧worker结束可返回给旧调用者，但不能重新写入已淘汰基准的缓存。以单调递增的基准日期管理缓存代际，较早请求晚到也不能把当前基准倒退。
- 每次读取重新检查T、日历覆盖和完整性；缓存不是过期数据豁免。过期缓存不能掩盖源失败。
- 同键共享在途任务，单个调用者取消不取消别人使用的worker；全批到期返回已完成部分，worker在9秒内结束，不无限挂起。
- `close()`幂等，先禁止新请求，再取消/等待worker并关闭session。取消首个close调用者后仍能完成回收；重载使用新客户端实例。
- 取消必须传播，不把`CancelledError`转为普通分析失败。宿主是否先排空事件处理尚需加载验证；实例终止标记须在历史完成后、提供商异步解析返回后各检查一次，至少保证客户端关闭后不重新开session、不继续生成趋势或新发起LLM。已在执行的宿主事件和LLM是否由宿主取消，另作加载验收，不将客户端close等同于排空全部宿主调用。
- 当前行情采集仍有原18秒预算；历史12秒与LLM为后续独立预算。经真实验收及用户确认，趋势LLM预算调整为90秒，快照仍为30秒；整条趋势命令最坏约120秒加绘图、清理及发送耗时，文档如实说明。

## 5. 指标计算与LLM分工

`trend_analysis.py`以纯函数构建趋势上下文；不调用网络或模型。输入历史已经通过校验，指标按完整精度计算，展示时舍入。

| 指标 | 固定定义 |
| --- | --- |
| 5/10/20日累计涨幅 | `100 * (C[T] / C[T-n] - 1)`，不是每日百分比相加 |
| MA5/MA10/MA20 | 含T在内最近n个收盘价算术均值 |
| 均线偏离 | `100 * (C[T] / MA_n - 1)` |
| 20日波动 | 最近20个相邻交易日简单收益率的样本标准差，乘100，不年化 |
| 20日价格区间 | 含T的最近20日最低low与最高high；称“观察区间”，不当作已验证支撑阻力 |
| 成交额变化（可缺失） | `最近5日平均金额 / 最近20日平均金额`；20日均完整、统计范围一致且分母大于0才计算 |

不输出未经验证的技术评分、胜率或上涨概率。价格/均线与收益率只是描述输入，不能声称有预测能力。

模型输入含：程序固定的基准/观察日期、完整当前文字行情（明确时间质量）、五指数历史状态、每只可用指数最近10日收盘与日涨跌、上述指标、来源/缓存/局限。历史与快照不互相补字段。第一条日涨跌需有前一日收盘，否则标未知。

模型需对有效指数分别给“偏强/偏弱/震荡/证据不足”，再给整体判断。上证、深证、沪深300任一缺失时，整体固定为“证据不足”，仍可解释有效指数；三者有效仅代表可讨论整体，不代表统计可信。核心指数明显分歧必须解释分化，不能用五只指数上涨数量冒充全市场宽度。

这些方向是LLM的定性研判，不是程序规则预测。首版继续使用纯文本输出；固定标题、禁止编造等依靠提示词约束，不能保证模型永远遵守，也不以脆弱正则宣称事实验证。基准日期、可用性和失败说明由程序输出，不交由模型决定。

## 6. 拟采用的完整趋势提示词

原快照prompt保留给关闭趋势及全部历史不可用的路径。趋势prompt放在`trend_analysis.py`，供上下文格式化使用：

```text
你是一名谨慎、客观的A股指数分析助手。仅依据下面的数据，分析基准交易日
之后第3至第5个交易日的趋势倾向。此任务不要求次日涨跌预测。

优先遵守以下事实边界，无法证实时省略结论：
1. 原样沿用程序给出的T+3/T+5交易日期；周末和休市日不计入，不能称为自然日或日历日。
2. 成交额比较未知时，只能写“成交额比较未知，无法判断量能”。单日绝对成交额不能证明放量、
缩量、成交活跃、买盘支撑或增量资金；价格涨跌也不能证明资金流入流出。
3. 输入仅有基准日均线值，不能据此声称均线已经拐头或连续多日上行/下行。
累计涨跌不是连续涨跌天数；只引用能由输入直接支持的数字和比较，不补全故事。

查询时间（北京时间）：{current_time}
基准交易日与收盘口径：{baseline}
观察区间及当前已进入的阶段：{horizon}
当前行情（独立快照，不作为已完成日线）：
{market_data}
历史日线摘要、来源、样本量与已计算指标：
{trend_data}
程序判定的数据质量及整体分析权限：
{quality_notes}

输出约500—700字纯文本，按以下标题分段，不使用加粗或表格。各段简洁，避免重复论据：

市场状态
用约70字简述当前表现和近期趋势，区分已完成日线与当前快照；不要逐项复述行情。

3—5交易日趋势
对有有效历史的指数分别给出偏强、偏弱、震荡或证据不足的判断，每只指数最多一句。
仅在程序允许时给出整体倾向；否则写“整体证据不足”。解释指数分化。
本段合计约300字，引用最关键的两项历史依据，并明确至少一项反向证据或尚未满足的条件。
判断属于推测，不将均线排列、连续上涨或历史趋势写成未来必然延续。

观察条件
用约150字说明到第3个交易日应观察什么，到第5个交易日哪些表现支持或否定原判断。
可以引用输入中的均线和历史区间作为参考；不得虚构价格目标、支撑阻力、
未来涨幅或买卖点。若基准区间已开始，不得把它说成从查询时刻重新计时。

数据局限
用约80字如实披露缺失指数、样本不足、缺失成交额、混合来源、时间未知或缓存状态。
没有已知反向证据时说明数据维度有限，不得编造反向事实凑段落。

约束：不要自行补查或假装查到数据；不编造新闻、政策、行业板块、资金流向，
不把指数涨跌数量当作全市场股票涨跌家数。缺失值不是零。
不得输出数字概率、胜率、主观置信度评分或具体投资操作建议。
数据不足时允许不作方向判断。优先保证依据、反证和局限完整，不机械截断正文。
结尾注明“趋势研判仅供参考，不构成投资建议”。
```

固定程序标题放在模型正文前：基准、观察日期、历史可用指数数、方法未验证预测准确率。程序标题不因模型错误叙述而改变；模型仍可能写错正文，README须保留这个限制。

| 推送LLM关闭、普通大盘/速报/单指数命令 | 不创建历史网络任务 |
| 新开关关闭 | 原快照分析与原历史报价跳过逻辑保留 |
| 周末/已核实节假日，有截至T的合格历史 | 可生成明确标明T的趋势，不因快照不在今天而直接跳过 |
| 部分历史失败 | 只分析合格指数，程序列缺失项；核心指数不足时整体证据不足 |
| 全部历史失败/未知年份/日历冲突/更新中 | 明确“趋势不可用”原因；按原快照规则决定是否进行一次快照LLM解读，不能假装完成趋势预测 |
| 有历史，但当前快照时间未知或落后T | 可以根据合格历史分析，指出快照无法反映当前，禁止借快照确认趋势 |
| LLM空白/异常/超时 | 保留原行情或卡片，附“趋势解读暂不可用”；不声称已有方向结论 |
| 图片失败 | 复用同一次解读回退完整文字，不再次获取历史或调用LLM |

同一分析请求最多调用一次LLM。历史失败后在调用LLM之前选定快照prompt；不先调用趋势再调用快照。旧的“早于今天跳过”判断只适用于快照路径，不能直接删掉，也不能让它拦截合格的周末趋势路径。

`/大盘状态`增加配置是否开启、日历覆盖年份及最近历史结果状态，注明检查时间；读取状态不发起网络请求，重载后显示“尚未查询”，不能把上次成功永久显示为当前可用。

## 9. 验收与开发顺序

详细任务见[实施计划](../plans/2026-10-23-market-trend-3-5d-plan.md)。依次完成：公开接口核实；日历/历史层；纯指标与prompt；主流程/配置接入；回归和文档。正常依赖顺序是每一步完成本步检查再进入下一步。

唯一环境例外：任务1因网络受阻时，可以按明确标注“假设、未验证”的接口契约继续任务2—5的解析、mock、纯计算和主流程离线集成；真实网络适配保持“未验收”，任何未确认完成语义的源运行时必须拒绝趋势，不能用假设布尔值放行生产结果。最终仅可交付“离线闭环完成、真实接口验收受阻”。本方案的新开关默认关闭，接口验收通过前不作默认启用、完整可用或发布完成声明。该例外不允许改换总体方案或安装额外服务。不自动提交、推送、发布或操作宿主。

验收分层：

1. 文档：来源链接、公式、日期例子、参数名与接口签名一致。
2. 静态：Python语法、Ruff check/format、JSON格式、diff空白。
3. 模拟：固定响应覆盖正常、错误、降级、并发、取消、日历和混合来源；不发送实际消息。
4. 真实历史源只读核实：五指数真实字段及页面交叉核对、收盘前后数据行为，不能由mock替代。
5. AstrBot加载/重载：只有用户授权操作宿主时进行，确认开关读取与session回收。
6. QQ联调：必须有明确群发送授权才执行；定时推送授权不由本规划隐含获得。

预测准确率不列为首版通过条件。后续若评估，应事前留存当时输入与结论，按时间滚动评估3日和5日结果、报告样本量/覆盖率并比较简单基准；不能随机混合过去未来，不能只选“说对”的案例，也不能把历史重放LLM视为严格前瞻测试。
